# ORGANE EVENT MATRIX

## Purpose

This document maps real system events
to their narrative cognitive organ flow inside Kao.

It does not replace kernel mechanics.
It provides an operator-readable event interpretation layer.

---

## Canonical matrix

| Real event | Narrative perception | Primary organ | Secondary organ | Safety organ | Action organ | Sovereign outcome |
|---|---|---|---|---|---|---|
| USB device inserted | external object enters system boundary | Bloom | Rekon | Sentinel | Syfer | Kao allows inspection or refuses access |
| New file appears in watched area | state surface changed | Bloom | Rekon | Sentinel if suspicious | Syfer if approved action is needed | Kao integrates state change |
| Unknown process starts | runtime anomaly emerges | Bloom | Rekon | Sentinel | Syfer if containment is required | Kao preserves integrity |
| Configuration file changes | system structure has shifted | Bloom | Rekon | Sentinel | Syfer if rollback or apply is required | Kao validates continuity |
| Network connectivity changes | external reachability changed | Bloom | Rekon | Sentinel if trust boundary is affected | Syfer if mode switch is required | Kao adapts runtime posture |
| Provider fallback occurs | cognitive route degraded or shifted | Bloom | Rekon | Sentinel if policy is violated | Syfer if correction is needed | Kao preserves stable operation |
| Repeated command failure | execution pattern becomes unstable | Bloom | Rekon | Sentinel if risk escalates | Syfer if repair is validated | Kao keeps control of execution |
| High cognitive heat | session intensity rises | Bloom | Rekon | none by default | none by default | Kao increases awareness |
| Low cognitive heat / long idle | session cools down | Bloom | none | none | none | Kao preserves calm continuity |
| Mutation requested by operator | change is intentionally requested | Bloom | Rekon | Sentinel | Syfer | Kao decides and integrates result |
| Suspicious mount / permission anomaly | trust boundary may be compromised | Bloom | Rekon | Sentinel | Syfer only if validated | Kao may refuse continuation |
| Service crash | operational organ failed in runtime | Bloom | Rekon | Sentinel if integrity is affected | Syfer for restart / repair | Kao restores continuity |

---

## Interpretation notes

### Bloom
Perceives the event and gives it cognitive visibility.

### Rekon
Checks what is actually happening in the real system.

### Sentinel
Validates system safety when the event touches trust, integrity, or irreversible risk.

### Syfer
Acts only when an action has been validated and is required in the real system.

### Kao
Remains sovereign and integrates the final meaning of the event.

---

## Principle

A real event must always remain:
- technically explainable
- narratively readable
- operationally actionable
